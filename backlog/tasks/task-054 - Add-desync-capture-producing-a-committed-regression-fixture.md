## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
On a lockstep checksum mismatch, capture a desync fixture: dump the replay/input log plus both peers' full state, so the failure becomes a committed regression fixture rather than a one-time bug report. A deliberately corrupted peer (e.g. one that drops or reorders an input) must produce a fixture that then fails Tier-D until the underlying bug is fixed, turning every desync into a permanent addition to the regression suite the same way task oracle:fuzz promotes fuzz failures into the corpus.
<!-- SECTION:DESCRIPTION:END -->

## Notes

`LockstepSession` (`game/simulation/lockstep_session.gd`) gained two public latency fields (stored
at construction, needed to reconstruct an equivalent session from a fixture) and one method,
`capture_fixture(tick, checksum_a, checksum_b) -> Dictionary`, which builds a JSON-safe snapshot of
both peers -- each side's stringified checksum (avoiding the same JSON-number-precision issue
`docs/corpus-format.md`'s `"c"` field already works around), full `input_log()`, and full
`world.serialize()["bytes"]` -- plus both link latencies (AC#1).

The existing single-actor oracle-corpus JSONL format (`docs/corpus-format.md`) has no room for a
two-replica artifact, so this is a new, separate fixture type rather than an extension of that
schema -- full rationale in `backlog/decisions/decision-037`. One fixture is committed:
`game/tests/desync_fixtures/corrupted_player0_input.json`, generated by
`game/tests/test_desync_fixture.gd` reusing the exact corrupted-peer injection already proven in
`test_lockstep_session.gd`'s corrupted-input test (AC#2's "e.g." permits any concrete corruption; a
second, novel corruption method would only add risk for no added coverage).

`test_desync_fixture.gd` doubles as the fixture's manual generator and its automatic regression
check, mirroring `reference/oracle/fuzz.mjs`'s promotion-step posture: every ordinary `task
game:test` run re-derives the fixture live from the corrupted-peer scenario and deep-compares it
against the committed file; only `DESYNC_FIXTURE_REGEN=1` (re)writes that file, never a normal test
run. Verified the regression contract works both directions, not just asserted it: hand-corrupted
one field of the committed fixture, confirmed `task game:test` then fails
("live desync capture no longer matches the committed fixture"), and confirmed restoring the file
makes it pass again (AC#2, AC#3).

### DoD#2 -- backlog/decisions/decision-037

The two-replica fixture format is new design with no `reference/snake.html` analogue to diverge
from (the oracle has no lockstep/networked concept at all) -- recorded in full in `decision-037`,
including why this is a new fixture type rather than an extension of the existing corpus schema.
